# Decisions

Append only. Format: `- D-nnn · date · decision · why · consequence`.

- D-001 · 2026-10-25 · Engineering process copied from the health-system repo (rules, ledger, hooks, agents, security gate), plus CodeQL, dependency review, Dependabot, Trivy, zizmor, OpenSSF Scorecard and a Claude security review on PRs; third-party actions pinned to commit SHAs. · Proven on M0 of the health platform; the March 2026 trivy-action tag hijack (CVE-2026-33634) showed tag pins are not enough. · Dependabot keeps the SHAs current.
- D-002 · 2026-10-25 · Stack is TypeScript (John): pnpm + Turborepo monorepo with `apps/mobile` (Expo, Android first), `apps/web` (Next.js), `apps/worker` (Node, Anthropic TypeScript SDK), `packages/core`; self-hosted Supabase + PowerSync; users bring their own Anthropic API key, stored encrypted. pnpm 10 and Node 24 pinned. · One language across mobile, web and worker; nothing bills John for other users. · CI runs `make ci`; Dependabot npm, docker, actions; CodeQL javascript-typescript; `.npmrc` node-linker=hoisted for Expo.
- D-003 · 2026-10-25 · Code-scanning uploads and dependency review run only when the repository variable `CODE_SCANNING` is `true`. · The repo is private without GitHub Code Security, so SARIF uploads and dependency review fail (PR #1 first run). · Trivy and zizmor fail the job on high or critical findings instead; turning the variable on restores the Security tab.
- D-004 · 2026-10-25 · The repo is public (John). · It is meant to be shared and self-hosted, holds code only, and public repos get CodeQL, dependency review and the Security tab free. · John sets `CODE_SCANNING=true` after the switch; no personal data or secrets ever go in the repo.
- D-005 · 2026-10-25 · Security checks allow two high findings reached only through `@expo/cli`, the Expo dev CLI (John): node-forge 1.4.0 GHSA-86w9-cpqp-85rv and zod 3.25.76 GHSA-mrhx-c7xc-m3w5 in dependency review (`allow-ghsas`), and the same zod issue as CVE-2023-54404 in Trivy (`.trivyignore`). · Neither ships in the app bundle; node-forge has no fix and the zod fix is zod 4, which `@expo/cli` 58.1.15 does not support (M0-02 PR #3). · Remove each entry when `@expo/cli` takes a fixed version; Dependabot's Expo group surfaces it.
